## bug1_dungeon_gen (`dungeon-gen`)

**symptom**
Building Ember Crypt floors: `gst dungeon-gen --mode bsp` -> `gst map-to-godot` produced a TileMapLayer with no cells, and the generated map had no room rectangles to place spawn, key and stairs objects in.

**reproduce**
```
$ GST_ROOT=<2.4.0 worktree> bash repro/bug1_dungeon_gen.sh
```
```
bsp 34x22 seed=701: 8 rooms, 1 connected region(s) -> f1.txt/.png/.json
tilesets: null
layers: ['dungeon']
1 layer(s), 0 cell(s) -> f1.tscn
start (4, 2): 352 of 352 walkable tiles reachable, 0 cut-off area(s)
0 of 0 object(s) reachable
start (4, 2): 748 of 748 walkable tiles reachable, 0 cut-off area(s)
0 of 0 object(s) reachable
exit=0
```

**investigate 1**
Open the generated f1.json: there is no `tilesets` key at all and only one layer (`dungeon`). Tiled and every kit consumer that maps GIDs to tiles need a tileset with firstgid.

**investigate 2**
Read dungeon-gen/dungeon_gen.py (2.4.0) `to_tiled()` at line 109: it returns width/height/layers only; no tilesets, no layer ids, no nextlayerid/nextobjectid.

**investigate 3**
`main()` line 128 calls `to_tiled(g)` without the `rooms` list that `bsp()` already returns, so room rectangles are computed and thrown away.

**investigate 4**
map-to-godot resolves each GID through the map tilesets; with none it writes `0 cell(s)`.

**root_cause**
`to_tiled()` emitted a map without any tileset (and dropped the BSP rooms), so GIDs 1/2 resolved to nothing in map-to-godot and there was no room metadata for object placement.

**symptom**
Ember Crypt actor clips: build.sh line 130 passes `--fps 'player-walk-*=10,boss-charge=12' --once 'player-idle-*'` to anim-from-folder. **investigate 1**
Run anim-from-folder with `--fps 'walk-*=10' --fps idle=4 --once 'idl*'` on 6 frames: walk clips come out at 8 fps (the default), idle loops, and a WARN names 'idl*' as unknown.

**investigate 2**
Read anim-from-folder/anim_from_folder.py (2.4.0): `--fps` (line 102) and `--once` (line 104) are plain string options, so argparse keeps only the last occurrence.

**investigate 3**
Line 116 parses fps into a dict keyed by literal names; `pack()` line 86 does `fps.get(k, default_fps)`, an exact-name lookup, so 'walk-*' never matches 'walk-down'.

**root_cause**
--fps/--once were single-value options looked up by exact clip name: repeated flags overwrote each other and glob keys never matched.
